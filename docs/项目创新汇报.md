## 一、项目背景与立项依据

### 1.1 业务痛点

随着国家反诈工作深入推进，中国移动宁夏公司依托反诈模型对高风险号码实施关停管控，有效遏制了电信诈骗行为。然而，在大规模模型关停实践中，不可避免地存在**一定比例的误伤**——部分正常用户因模型误判被关停，由此引发用户不满，并在微博、知乎、百度贴吧、抖音、小红书等**自媒体平台发表投诉言论**，形成负面舆情。

与此同时，监管实践中还发现另一类现象：**少数真实诈骗用户**也会通过发帖、组织集体投诉等方式向运营商施压，试图借助舆论力量迫使运营商恢复号码，以规避监管。

这两类舆情叠加，对公司在以下维度带来考核风险：

| 风险维度 | 具体影响 |
|---------|---------|
| 品牌形象 | 负面帖子传播，引发公众误解 |
| 监管考核 | 被投诉上升，工信部考核扣分 |
| 业务合规 | 若无法区分误伤与恶意施压，处置决策存在盲区 |
| 诈骗反制 | 诈骗用户借舆论迫使恢复，削弱反诈效果 |

### 1.2 现状问题

目前，公司缺乏针对**反诈关停引发舆情**的系统化监测手段：

- 💬 **发现滞后**：依赖人工偶发发现，无法实时感知
- 📊 **数据分散**：各平台舆情数据孤立，缺乏汇总分析
- 🔍 **无法区分**：正常投诉与恶意施压混在一起，难以甄别
- 📋 **缺少档案**：无法对相关用户建立长期追踪档案
- ⏱️ **响应被动**：等到舆情爆发才处置，应对成本高

---

## 二、项目目标

本项目旨在构建一套**自动化、智能化、可持续运营**的反诈微舆情监测工具，实现：

1. **自动监测**：7×24小时持续抓取主流自媒体平台相关舆情内容
2. **智能分级**：基于关键词 + NLP 情感分析对舆情进行高/中/低风险分级
3. **类型识别**：区分正常误伤投诉用户与疑似诈骗用户施压行为
4. **数据报表**：每日自动生成结构化 Excel 报表，供内部审核决策
5. **用户定位**：提取涉及手机号，辅助核查关停时间，协助内部用户定位
6. **长期档案**：建立用户舆情档案，支持跨时间段的风险追踪

## 三、技术方案

### 3.1 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                    定时调度层（APScheduler）                  │
│                每60分钟触发一次爬取；每日8:00生成报表           │
└──────────────────────┬──────────────────────────────────────┘
                       │
       ┌───────────────▼───────────────┐
       │         爬虫管理器             │
       │  WeiboCrawler  TiebaCrawler   │
       │  ZhihuCrawler  （更多平台扩展）│
       └───────────────┬───────────────┘
                       │ 原始帖子数据
       ┌───────────────▼───────────────┐
       │         NLP 分析引擎           │
       │  关键词匹配 + 情感分析          │
       │  施压模式识别 + 风险评级         │
       └───────────────┬───────────────┘
                       │ 结构化分析结果
       ┌───────────────▼───────────────┐
       │        SQLite 数据库           │
       │  舆情帖子表 + 用户档案表        │
       └───────────────┬───────────────┘
                       │
       ┌───────────────▼───────────────┐
       │       Excel 报表生成器         │
       │  综合概览 / 高风险明细          │
       │  全量数据 / 用户核查清单        │
       └───────────────────────────────┘
```

### 3.2 关键技术

| 技术点 | 实现方式 |
|--------|---------|
| 多平台爬虫 | Python requests + BeautifulSoup，支持微博/知乎/贴吧 |
| 中文分词 | jieba 分词库 |
| 情感分析 | SnowNLP 中文情感分析模型，输出 0~1 情感分值 |
| 风险评级 | 规则引擎（关键词权重 + 情感分值 + 传播量综合打分）|
| 施压识别 | 正则表达式模式匹配（集体投诉/曝光运营商等特征词）|
| 数据存储 | SQLAlchemy ORM + SQLite（可扩展为 MySQL）|
| 报表生成 | openpyxl 生成多 Sheet Excel，支持颜色分级显示 |
| 定时调度 | APScheduler 支持间隔任务 + Cron 定时任务 |

### 3.3 数据模型

**舆情帖子表（sentiment_posts）**  
记录每条监测到的帖子，包含平台、作者、内容、互动数据、分析结果。

**用户档案表（user_profiles）**  
以手机号为主键，汇聚同一用户在多平台的投诉记录，关联关停信息与处置情况。

**告警记录表（alert_records）**  
高风险舆情的告警流转记录，支持处置状态跟踪。

## 四、创新亮点

### 创新点一：面向反诈场景的细粒度舆情分级

不同于通用舆情工具，本项目针对**反诈关停业务场景**，定制化设计了三级风险分级体系，并特别增加了**疑似诈骗用户施压识别**维度，填补了行业空白。

### 创新点二：正常投诉与恶意施压的智能区分

通过构建**施压模式词库**（如"集体投诉""联合施压""曝光运营商"等），结合情感分析，实现对两类舆情用户的初步智能区分，辅助人工判断。

### 创新点三：舆情数据与用户关停数据的协同分析

报表中的**用户核查清单**自动提取帖子中提及的手机号，直接关联至内部关停系统的核查流程，实现舆情数据与业务数据的贯通，压缩人工核查时间。

### 创新点四：全流程自动化，零人工触发

从爬取 → 分析 → 报表生成，全流程自动完成，每日定时推送报表，运营人员无需手动操作。
